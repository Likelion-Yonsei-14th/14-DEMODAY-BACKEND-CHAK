# 안정성 점검 (서버가 멈추는 급의 위험)

2026-10-22 장애(RDS 비밀번호 자동 교체로 DB 연결 전부 실패, 헬스체크는 정상이라 감시가 못 잡음, 약 20시간 지속)를 계기로 코드와 인프라를 점검한 기록이다. 새 위험을 발견하거나 해소하면 이 표를 고친다.

## 한눈에 보기

| 13 | 마이그레이션이 시작할 때 자동 실행되고, 이미지를 되돌려도 스키마는 안 돌아감 | 중간 | 주의 (아래) |
| 14 | 라이브 서버의 `run.sh`가 템플릿과 다름(손으로 고침) | 중간 | 주의 |
| 15 | 프론트(Vercel)가 단일 의존이고 미들웨어 실수가 전체를 막을 수 있음 | 중간 | 문서화 |

## 열려 있는 것

**9. 손님 기록 무제한 생성.** `/api/public/**`는 로그인이 필요 없고, 쿠키가 없으면 요청마다 손님 행(`guest_identities`)과 이벤트가 생긴다. 사용자별 분당 제한은 있지만 쿠키를 버리고 반복하면 우회된다. 공격 한 번으로 DB가 부풀거나 연결이 마를 수 있다. 앱 앞에 CloudFront가 있지만 요청이 Vercel을 거쳐 들어와 서버가 보는 IP가 Vercel 주소라서, 앱에서 IP로 막으면 정상 사용자가 함께 막힌다. 해결책은 둘이다.
- CloudFront에 AWS WAF 속도 제한 규칙을 붙인다(월 약 $6 + 요청당 요금, 가장 확실).
- 프론트 프록시에서 방문자 IP를 헤더로 전달해 앱이 그 값으로 제한한다(Vercel 미들웨어는 이 프로젝트에서 장애를 냈으니 프리뷰에서 충분히 검증).

**10. 단일 서버·단일 AZ.** EC2가 고장 나면 AWS가 자동 복구하지만 수 분 걸리고, DB 장애는 복구될 때까지 기다려야 한다. 다중 AZ(RDS 월 약 +$19)와 서버 2대+로드밸런서(월 약 +$25)로 줄일 수 있다. 지금 규모에서는 감수하되, 트래픽이 늘면 가장 먼저 올릴 항목이다.

**11. `chak-prod` 스택은 업데이트하지 않는다(서버가 교체됨).** 2026-10-23에 이 스택에 최소 변경을 올려 변경 세트를 미리 보니 `Server`(EC2)가 **교체(Replacement: True)**로 나왔다. 템플릿의 `ImageId`가 "최신 Amazon Linux 이미지"를 가리키는 동적 참조라서, 스택을 어떤 내용으로 업데이트하든 최신 이미지로 바뀌며 서버가 새 인스턴스로 교체되고, 손으로 고친 설정이 사라지고, 공인 DNS가 바뀌어 CloudFront가 갱신되는 동안 중단된다. (`UserData`는 배포된 것과 같았다.) 그래서 `chak-prod`는 건드리지 않고, 경보는 별도 스택(`chak-alarms`)으로, DB 설정은 RDS 콘솔에서 바꾼다. `chak-prod`를 업데이트해야 한다면 먼저 `ImageId`를 현재 서버의 AMI ID로 고정하고, 변경 세트에 `Server` 교체가 없는지 확인한 뒤 새벽에 한다.

**13. 마이그레이션.** Flyway가 앱 시작 때 자동으로 돌린다. 오래 걸리거나 테이블을 잠그는 변경은 점검 시간에 하고, 컬럼 삭제처럼 되돌릴 수 없는 변경은 두 번에 나눠 배포한다. 이미지를 롤백해도 이미 적용된 마이그레이션은 되돌아가지 않는다.

## 직접 실행할 것 (서버 쪽 포함)

1. **EC2 디스크 정리(한 번)** — AWS 콘솔 → EC2 → `chak-server` → 연결 → Session Manager에서:
   ```bash
   docker image prune -af --filter "until=168h"   # 일주일 넘은 안 쓰는 이미지 삭제(롤백용 최근 이미지는 남음)
   df -h /                                         # 사용량 확인
   ```
   주기적으로 하려면(`cronie`가 있을 때) `echo '0 4 * * 0 root docker image prune -af --filter until=168h' | sudo tee /etc/cron.d/chak-prune`.
2. **UptimeRobot 감시 URL 변경:** `https://www.chak.live/api/public/health` → `https://www.chak.live/api/public/health/db`. (기존 `/health`는 서버 자동 교체가 쓰므로 그대로 둔다.)
3. **경보 스택 만들기(`chak-alarms`)와 DB 설정.** 서버·DB와 별개의 스택이라 서버에 영향이 없다.
   - CloudFormation → 스택 생성 → `deploy/aws/chak-alarms.yaml` 업로드 → 파라미터 `AlarmEmail`(경보 받을 메일), `DbInstanceId`(`chak-prod-database-juxr0u7yq6j0`), `ServerInstanceId`(`i-073da940e5dc85daa`). 만든 뒤 받은 SNS 구독 확인 메일에서 "Confirm subscription"을 누른다.
   - RDS 콘솔 → `chak-prod-database-...` → 수정에서 ① 스토리지 자동 조정 켜고 최대 100GiB, ② 백업 보존 기간 7일, ③ 삭제 방지 켜기 → 계속 → "즉시 적용". (계정이 무료 플랜이면 일부 항목이 제한될 수 있다. 백업이 1일로만 되면 그대로 둔다.)
4. **채팅에 노출된 키 교체**(카카오·구글).

## 해결한 것의 확인 방법

- `/api/public/health/db`가 200이고, DB에 접속할 수 없을 때는 503이 나온다(자동 테스트 포함).
- 경보: RDS 연결 수가 15분 연속 0이면(앱은 유휴 연결을 계속 유지하므로 정상일 때는 0이 되지 않는다) 메일이 온다.
